# Дизайн импорта треков существующим артистам с папки

## Цель

Подготовить проект Miyu к обычному запуску на VPS и добавить отдельный ручной сценарий первичного импорта треков из папки. Скрипт не должен менять текущее базовое наполнение БД, создавать новых артистов или автоматически запускаться вместе с Docker Compose.

## Контекст

Проект уже имеет production-основу для VPS:

- `docker-compose.prod.yml` поднимает frontend, backend, nginx, Redis, ai-service и ai-worker.
- `backend/routes/artist.ts` создаёт треки со статусом `pending` при ручной загрузке.
- `backend/services/aiService.ts` ставит задачу анализа в ai-service через `/analyze/enqueue`.
- `ai-service/app/analysis/repository.py` записывает результаты анализа в `track_analysis` и `moderation_queue`, а также применяет итоговый статус модерации.
- `backend/routes/moderation.ts` содержит ручное одобрение и отклонение треков модератором/admin.

## Источник треков

Скрипт читает аудиофайлы из папки:

```text
seed-content/tracks/
```

Путь можно переопределить переменной окружения:

```env
SEED_TRACKS_DIR=../seed-content/tracks
```

Формат имени файла:

```text
Автор - Название.mp3
```

Пример:

```text
Kira - Neon Sky.mp3
Kira - Rain Again.mp3
Miyu Artist - Night Walk.mp3
```

## Поведение скрипта

Скрипт выполняется только вручную отдельной командой, например:

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml run --rm backend npm run seed:tracks
```

Он не добавляется в `entrypoint`, `CMD`, `depends_on` или автозапуск compose.

Для каждого файла скрипт:

1. Проверяет расширение аудиофайла.
2. Парсит автора и название из имени `Автор - Название`.
3. Ищет существующего артиста в таблице `users` по `username = Автор` и `role = 'artist'`.
4. Если артист не найден — пропускает файл и добавляет запись в отчёт.
5. Проверяет, нет ли у найденного артиста уже трека с таким названием.
6. Если дубль найден — пропускает файл.
7. Копирует файл в `uploads/tracks` с безопасным уникальным именем.
8. Создаёт запись в `tracks` со статусом `pending`.
9. Ставит трек в AI-анализ через существующий backend-клиент `enqueueAnalyzeTrackAndForget`.
10. В конце выводит отчёт: импортировано, пропущено как дубли, пропущено из-за отсутствующего артиста, ошибки.

## Модерация и AI-анализ

Скрипт не публикует треки напрямую. Все импортированные треки создаются как `pending`, как при ручной загрузке артиста.

Дальше используется существующая логика:

- чистые треки могут стать `approved` через AI auto-approve;
- спорные треки остаются `pending`;
- проблемные треки попадают в `moderation_queue` со статусом `ai_flagged`;
- admin/moderator вручную одобряет или отклоняет их через существующий moderation UI/API.

Для этого на VPS `AI_SERVICE_ENABLED` должен быть `true`, иначе импортированные треки останутся без анализа в `pending`.

## Изменения в проекте

Планируемые файлы:

- `backend/scripts/seed-tracks-from-folder.ts` — новый ручной импортёр треков существующим артистам.
- `backend/scripts/seed-tracks-from-folder-utils.ts` и `backend/scripts/seed-tracks-from-folder.test.ts` — pure helpers и focused-тесты для формата файлов.
- `backend/package.json` — добавить npm-скрипт `seed:tracks`.
- `backend/package-lock.json` — синхронизировать lockfile, чтобы production Docker build проходил `npm ci`.
- `backend/.dockerignore` — исключить локальные `node_modules`/`dist`, чтобы Docker-сборка не копировала Windows-зависимости поверх Linux `npm ci`.
- `docker-compose.prod.yml` — примонтировать `seed-content` read-only без автозапуска импорта.
- `.env.production.example` — добавить пример `SEED_TRACKS_DIR`.
- `.gitignore` и `seed-content/tracks/.gitkeep` — сохранить структуру папки и не коммитить аудио.
- `docs/UPLOAD_TO_VPS.md` — обновить инструкцию обычного запуска и отдельного импорта треков.

Не создаём новых артистов, пользователей, пароли, artist_profiles, альбомы или обложки.

## Ограничения первой версии

- Поддерживается только формат имени `Автор - Название`.
- В первой версии не импортируются альбомы и обложки.
- Если имя артиста в файле не совпадает с `users.username`, файл пропускается.
- Повторный запуск не должен создавать дубли для пары `artist_id + title`.
- Скрипт предназначен для одноразового или редкого ручного запуска на уже поднятом backend-контейнере.

## Проверка

Минимальная проверка после реализации:

1. Запустить build backend, чтобы TypeScript-скрипт компилировался.
2. Подготовить маленькую тестовую папку с одним файлом для существующего артиста и одним файлом для несуществующего артиста.
3. Запустить `npm run seed:tracks` с `SEED_TRACKS_DIR` на тестовую папку.
4. Проверить, что найденный артист получил трек со статусом `pending` или результатом AI-прохода.
5. Проверить, что файл неизвестного артиста пропущен.
6. Повторить запуск и убедиться, что дубль не создан.
